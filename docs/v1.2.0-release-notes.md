# OpenCADStudio v1.2 — Native GIS and Python

v1.2 connects editable feature data and managed CPython to the same local-first
project used by CAD and LiDAR.

## Native GIS

- OGC point, multipoint, line, multiline, polygon, and multipolygon geometry
  with WKB and GeoJSON round trips.
- GeoPackage feature tables preserve stable feature ids and native SQLite
  text, integer, real, boolean, and null values.
- Attribute-table filtering, deterministic multi-field sorting, selection,
  field calculation, and keyed joins.
- Topology checks for open rings, duplicate vertices, self-intersections, and
  overlapping polygon interiors.
- Desktop commands:
  - `GISIMPORT <file.gpkg|file.geojson>`
  - `GISLAYERS`
  - `GISTOPOLOGY [layer]`
  - `GISEXPORT <layer> <output.gpkg|output.geojson>`
  - `GISTRANSFORM <layer> <target-epsg>`
- Imported layers are cataloged as external, read-only project sources.
  Transformations are explicit and append provenance to project history.

## Geodesy

- Horizontal CRS plans report every hop, unit, backend, nominal accuracy, and
  execution time.
- Compound XYZ plans carry horizontal and vertical CRS identifiers and a
  validated coordinate epoch.
- Local constant-offset vertical transformations execute with provenance.
- Required grid/geoid operations fail closed until the named, checksummed grid
  is available through a validated backend; the application never silently
  substitutes an approximate height.

## Python

- CPython remains isolated in a worker process and communicates with the app
  over the same main-thread request bridge used by Rhai.
- `ocs.current_project()`, native feature-layer operations, named section
  creation, and `ocs.tools.list()/run()` expose live application state.
- Script-tool JSON manifests validate entry points and parameter schemas.
- Environment health reports interpreter version, virtual-environment status,
  and `ocs` package availability.
- Downloaded-script trust is tied to the canonical file path and SHA-256
  content digest, so modifying an approved script makes it untrusted again.

## Compatibility

- Existing schema-1 `.ocsproj` files open unchanged.
- Large geometry and point sources remain external; the project stores
  references, settings, and audit data.
