# OpenCADStudio v2.1.0 — 3MF editing and production terrain workflows

v2.1.0 delivers the stable production slice of the
[3D development plan](3d-development-plan.md): one coherent workflow where
surveyed terrain and imported surface models meet the CAD drawing, instead of
separate model-viewer and point-cloud features.

## 3MF Core import

- Streamed, forward-only 3MF Core parser over the OPC package — the model XML
  is never copied into memory, so multi-hundred-megabyte packages stay
  bounded. Verified against a 48 MB real-world city model (4.37M triangles,
  2.27M vertices, 86 objects): full import in about 4 seconds in a release
  build.
- Meshes, components, build items, and their affine transforms resolve into
  persistent, editable DWG `MESH` entities; object names become `3MF/…`
  layers and base-material colors are preserved per triangle group.
- Units are mapped to the drawing header (micron through foot). The import
  opens as an unsaved drawing so QSAVE can never route a CAD writer back over
  the source package.
- Package hardening: entry-count, expansion, path-traversal, and
  compression-ratio (zip-bomb) limits; vertex/triangle ceilings; component
  cycle and depth limits; required unknown extensions are rejected.
- Import diagnostics report object counts, units, bounds, materials,
  components, build items, and any skipped package parts (thumbnails,
  textures, model settings) on the command line.
- `.3mf` joins the open dialog filters, the `OPEN` command, Recents, and the
  Windows installer file associations.

## Mesh display LODs

- Unsubdivided triangle MESH entities take a direct path into the shaded mesh
  pipeline that skips redundant re-triangulation and edge hashing, so
  multi-million-triangle imports cache in seconds instead of locking the UI.
- Meshes above 50,000 triangles gain two additional index-preserving display
  LODs (border-locked simplification); the exact source geometry is kept for
  editing and measurement, and LODs are display-only.
- 3MF opens default to a shaded, fitted model view without triangle-edge
  overlay.

## Mesh editing and 3MF export

- `MESHDIAGNOSE` reports components, manifold/boundary state, invalid indices,
  degenerate and duplicate faces, isolated vertices, and winding conflicts.
- `MESHWELD`, `MESHFILL`, `MESHFLIP`, `MESHORIENT`, and `MESHDELETEFACE`
  provide bounded, selection-scoped, undoable repairs while rebuilding only
  the edited mesh's derived display caches.
- `EXPORT3MF` writes exact source MESH geometry, drawing units, layer/object
  names, and base-material colors. Polygon faces are triangulated for 3MF Core.
  Export preflights indices and triangle limits and publishes through an
  adjacent temporary file, so a failed export cannot destroy an existing
  package.
- Import options support centering, unit override, and material preservation
  for programmatic workflows. Default OPEN behavior remains loss-averse.

## Terrain draping over LiDAR

- New surface-sampling and path-draping API in `ocs_pointcloud`
  (`drape_path`): input validation, a hard 1,000,000-point ceiling per
  operation, vertical offsets, and atomic failure — a sample outside the
  surface produces no partial output.
- `POINTCLOUDDRAPE [spacing] [vertical-offset]` copies selected lines, arcs,
  circles, ellipses, splines, closed footprints, 2D/3D polylines, and MESH
  entities onto terrain. Sources are never modified; coverage failure is
  atomic and every successful output set is one undoable transaction.
- Draping samples class-2 ground points when available and clearly reports
  fallback to all resident points.
- `POINTCLOUDBREAKLINECHECK [maximum-grade]` validates selected terrain
  breaklines for crossings, repeated vertices, zero-length segments, and
  elevation spikes. `POINTCLOUDSURFACEAT <X> <Y> [reference-Z]` reports the
  interpolated surface elevation and signed vertical distance.
- Full-density DTM, DSM, and hillshade exports are registered in the spatial
  project as fingerprinted, CRS-aware derived sources with their source ID,
  filter/resolution metadata, dimensions, point count, and regeneration
  recipe.
- A "Terrain and CAD draping" section in the LiDAR manager exposes ground
  classification, contours, drape, and DTM/DSM/hillshade export together.

## Verification

- `ocs_pointcloud` library suite: 74 tests, including drape densification,
  closed-path, atomic-failure, and unbounded-subdivision coverage.
- Desktop application suite includes 3MF package round-trip
  diagnostics, drape source extraction, indexed-mesh LOD exactness, generic
  quad-face fallback, and large-mesh LOD monotonicity.
- Platform (5) and spatial/geodesy (10) contract suites and the 5
  point-cloud shader contract tests pass unchanged.
- Opt-in stress fixtures cover real 3MF libraries (`OCS_3MF_STRESS_FILE` /
  `OCS_3MF_STRESS_DIR`) and full viewport-cache builds for large models; the
  two-million-point LiDAR scale gate continues to run in CI.
- The Boston HIGH production fixture passes import/export/re-import with 112
  mesh entities, 4,418,386 triangles, 2,373,706 vertices, identical bounds,
  and millimeter units; its complete render-cache build also passes.
- Supported and intentionally deferred features are recorded in the
  [v2.1.0 3D compatibility matrix](v2.1.0-3d-compatibility.md).
