# OpenCADStudio v1.1.0 — LiDAR Production Workstation

OpenCADStudio v1.1 moves the point-cloud workflow from a viewer-oriented CAD
attachment into a local-first spatial production foundation. Large source data
stays external and read-only; projects store references, fingerprints, named
objects, job state and provenance.

## Spatial projects and durable work

- New versioned `.ocsproj` manifests catalog local LAS/LAZ/COPC, E57-derived,
  CAD, raster, terrain, feature, mesh and service sources without embedding
  large files. Relative paths, absolute hints and fingerprints support project
  relocation and changed/missing-source detection.
- `SPATIALPROJECTNEW`, `SPATIALPROJECTOPEN` and `SPATIALPROJECTSAVE` connect the
  manifest to document tabs. Point sources, drawing CRS, active sections and
  named point selections round-trip through the project.
- Durable job records support queued/running/paused/cancelling/completed/failed
  states, checkpoints, retry, logs and restart recovery. Protected outputs use
  exclusive locks and adjacent partial files, publishing only after success.

## Reliable spatial viewing

- Section widths are fixed world/map units in the UI, CPU tile selector, GPU
  uniform and shader. Zoom no longer changes which physical corridor is shown.
- The unified LOD selector rejects off-screen tiles, applies the active section
  before budgeting points, and chooses the finest level that fits the budget.
- Point Cloud Manager diagnostics report visible/resident point and tile state
  consistently with the viewport pipeline.

## Production data paths

- Native local COPC hierarchy queries and HTTP byte-range COPC access use the
  same bounded query interface and never require a full remote download.
- ASTM E57 import streams every scan, applies scanner poses, converts spherical
  coordinates, preserves RGB/intensity and WKT coordinate metadata, and emits
  standard LAS/LAZ. Invalid records are counted and skipped explicitly.
- Processing extents support all data, 3D bounds, fixed world-space slabs and
  polygon plus vertical limits. Full-density visitors read physical source
  records instead of viewer samples or resident LOD tiles.
- Full-density two-pass rasterization produces bounded-memory DTM, DSM and mean
  grids. ESRI ASCII grids and hillshade PGM outputs are restart-safe.

## Classification, measurement and terrain

- Ordered classification pipelines provide ground, noise, rules, footprint
  building, centerline road and height/return vegetation stages with
  deterministic priority and per-stage histograms.
- Survey measurements cover point-to-point vector/azimuth/grade,
  point-to-plane, point-to-raster-surface and bounded exact cloud-to-cloud
  statistics.
- Raster DTM/DSM/mean surfaces, hillshade, existing contour/TIN generation and
  breakline validation cover the v1.1 terrain foundation. Breakline checks find
  too-few/duplicate vertices, zero-length segments, self-intersections and
  grade spikes.
- A typed, searchable production tool registry declares density, CRS,
  background execution, cancellation, checkpoint and undo requirements so
  ribbon, command line and scripts share the same contracts.

## Verification and packaging

- The release workflow now requires point-cloud core tests, shader contract
  tests and a complete desktop `cargo check` before packaging begins.
- The Windows MSI remains upgrade-compatible with earlier releases and bundles
  the desktop application, self-contained LiDAR classifier and DWG thumbnail
  provider.

## Compatibility notes

- `.ocsproj` schema version 1 is forward-guarded: newer unsupported schemas are
  rejected rather than partially loaded.
- Original LAS/LAZ/E57 files are never overwritten by processing operations.
- Existing drawing sidecars continue to load; `.ocsproj` complements them and
  is the durable multi-source project boundary for v1.1.
