# Open CAD Studio maintenance audit — September 5, 2026

## Scope

Reviewed the current native Rust/Iced app, drawing persistence and recovery,
background save/import/export paths, plotting input, automation document state,
update checking, and Windows release packaging. The substantial pre-existing
working-tree changes were preserved and are included in this build. They were
not reverted or represented as new work from this audit.

## Findings fixed

| Priority | Finding and user impact | Change and evidence |
| --- | --- | --- |
| High | Windows save fallback deleted the original before renaming the completed replacement, leaving a data-loss window. | Retry the replacement operation itself; fail without deliberately deleting the original. Real Windows sharing-lock test preserves original bytes, then successfully retries after the lock is released. |
| High | Pasted Unicode in a plot color could panic on UTF-8 byte slicing. Invalid hex could silently become black. | Shared strict color parser for the editor and legacy CTB reader; regression tests cover Unicode, invalid hex and blank/object color. |
| High | Compressed plot styles could expand without a memory ceiling. | Reject excessive declared content and cap actual decompression at 16 MiB; test uses an oversized compressed legacy file. |
| High | Automation NEW/OPEN retained previous-document history, selection, UCS, caches and leases. | Fresh document state on successful replacement; regressions cover undo/redo isolation, failed-open preservation, and lease release. The OPEN path also adopts a saved current layer when the source provides one. The stale-UCS test failed before the fix. |
| Medium | Save and update workers were immediately joined inside async futures, occupying executor threads while waiting. | Await a one-shot channel instead; regression proves another future can run while the worker is pending. |
| Medium | Import/export/printing worker panic could lead to a second panic when its response channel closed. | Shared background runner catches worker panics and reports thread-start/channel errors through normal result handling. |
| Medium | Update parser assumed compact JSON, could select nested fields and dropped surrogate-pair characters. | Use the existing JSON dependency; whitespace/nesting/emoji regression failed before the fix and passes afterward. |
| Medium | Plot fields could partially apply invalid input with little feedback. | Validate color, lineweight and screening before changing an entry; preserve the previous entry on failure. |
| Medium | Manual CI MSI builds could be labeled 0.0.0, breaking normal upgrade behavior. | Use the manifest version and reject release-tag mismatches. Local packager also checks executable version, required workers and the PROJ grid checksum. |

## Package and reproducibility

The version is 2.1.1. The MSI retains the existing upgrade code
`{BD6BCEAB-6C7A-4CE2-A62D-6EF06A92F8B1}`, installer features and file associations.
The local packaging script builds the app and thumbnail provider, checks the
existing bundled classifier and PROJ worker, validates the pinned grid, and runs
WiX compiler/linker validation. The separate verifier reads installer metadata,
extracts the cabinet and compares each application payload file against its build
input by SHA-256. The smoke script can then test the actual extracted executable.

See `v2.1.1-release-notes.md` for build commands. No GitHub release was published,
no source commits were made, and the existing installation was not upgraded.

## Limits and next improvements

This is a code, automated workflow and packaging review, not an exhaustive native
mouse/keyboard walkthrough. Installer execution on a clean Windows machine and a
full production-size GUI/GPU soak remain separate checks. The local MSI is
unsigned; trusted signing requires the configured release credentials.

The next useful investments are a repeatable native GUI and installer-upgrade
test harness, visible progress/cancellation for long 3D operations, and signed
release builds from an identified source revision. External-data tests marked
ignored are not included in the standard suite. The 2M-point stress test was
started but cancelled while the release build held Cargo's build lock; it remains
available as an ignored on-demand test and was not used as a pass/fail claim for
this package.
